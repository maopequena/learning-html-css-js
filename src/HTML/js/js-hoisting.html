Içamento

O comportamento padrão do JavaScript é mover as declarações para o topo do escopo atual, isso se chama hoisting (ou içamento).

Podemos declarar uma variável após usá-la no código; isto é içamento. Os dois exemplos abaixo, um usando içamento e o outro não, têm o mesmo resultado.

			
				x = 5; // Atribuir 5 a x

				elem = document.getElementById("demo"); // Encontrar um elemento
				elem.innerHTML = x;                     // Exibir x no elemento

				var x; // Declarar x

				OU

				var x; // Declarar x
				x = 5; // Atribuir 5 a x

				elem = document.getElementById("demo"); // Encontrar um elemento
				elem.innerHTML = x;                     // Exibir x no elemento

As declarações var e let

Variáveis definidas com let e const são içadas para o topo do bloco de código, mas não são inicializadas, isto é, o bloco de código sabe da existência da variável, mas não pode usá-la até que seja declarada.

Usar uma variável let antes de declará-la resulta em um ReferenceError. A variável fica em um tipo de "zona morta temporal" desde o início do bloco de código até ser declarada:

			
				carName = "Volvo";
				let carName; // ReferenceError

Usar uma variável const antes de declará-la é um erro de sintaxe, então o código simplesmente não executa:

			
				carName = "Volvo";
				const carName; // Nada acontece!

Inicializações não são içadas

O JavaScript iça apenas declarações, não inicializações. O Exemplo 1 abaixo não tem o mesmo resultado do Exemplo 2:

			
				// Exemplo 1:
				var x = 5; // Inicializar x
				var y = 7; // Inicializar y

				elem = document.getElementById("demo"); // Encontrar um elemento
				elem.innerHTML = x + " " + y;           // Exibir x e y

				// Exemplo 2:
				var x = 5; // Inicializar x

				elem = document.getElementById("demo"); // Encontrar um elemento
				elem.innerHTML = x + " " + y;           // Exibir x e y = "5 undefined"

				var y = 7; // Inicializar y

No Exemplo 2, faz sentido que y seja indefinido? Isso ocorre porque apenas a declaração var é içada e não a inicialização ("=7"). O JavaScript considera isso como uma declaração antes do uso, por isso y é indefinido.

Por causa do içamento, a prática recomendada é sempre declarar as variáveis no início do escopo.

use strict;

Esta não é uma declaração, é uma expressão literal. Seu propósito é indicar que o código deve ser executado em "modo rigoroso", em que não se pode, por exemplo, usar variáveis sem declará-las. Como é apenas uma sequência de caracteres, podemos deixá-la no código mesmo que o navegador não a compreenda, então a prática recomendada é sempre colocá-la no início do código.

Colocando o comando use strict; no topo do arquivo, isto é, no início do código, ele tem escopo global. Porém, também é possível declará-lo com escopo local, dentro de uma função.

Essa string ajuda a manter o código seguro. Por exemplo, sem o modo rigoroso, ao digitar um nome de variável incorretamente, você cria uma nova variável global, mas no modo rigoroso isso gera um erro. Neste modo também ocorrem erros ao atribuir valores a propriedades que não podem receber atribuições ou a propriedades, variáveis ou objetos inexistentes.

Neste modo também não é possível excluir variáveis, objetos ou funções com a declaração delete; duplicar um nome de parâmetro, usar literais numéricos ou caracteres de escape octais; usar eval, arguments, with.

Além disso, a palavra-chave this funciona diferentemente no modo rigoroso. Essa palavra chave refere-se a um objeto que chama uma função; se o objeto não estiver especificado, as funções no modo rigoroso retornarão undefined e no modo normal, o objeto global (a janela).

Palavras-chave que não podem ser usadas como nomes de variáveis

Algumas palavras-chave estão reservadas para uso atual e futuro no JavaScript e NÃO podem ser usadas como nomes de variáveis no modo rigoroso. São elas:

  • implements
  • interface
  • let
  • package
  • private
  • protected
  • public
  • static
  • yield
