Guia de estilo do JavaScript

Convenções de código

Sempre use as convenções de código para todos os projetos do JavaScript. Essas convenções abrangem:

  • Regras de nomenclatura e declaração para variáveis e funções.
  • Regras para o uso de espaços em branco, indentação e comentários.
  • Práticas e princípios de programação.

As convenções de código garantem a qualidade do código melhorando sua leitura e facilitando a manutenção.

Nomes de variáveis

Geralmente, usa-se o camelCase* para nomes de identificadores, como variáveis e funções, e os nomes devem começar uma letra.

* camelCase: a primeira palavra toda em letras minúsculas e as demais com a primeira letra em maiúscula.

Espaços entre os operadores

Sempre adicione espaços entre os operadores (+, -, *, /, %, **, || e =) e após vírgulas.

Indentação do código

Sempre use dois espaços para indentar blocos de código dentro de funções, matrizes ou objetos:

					
						function paraCelsius(fahrenheit) {
							return (5 / 9) * (fahrenheit - 32);
						}

Não use tabuladores para indentação, use espaços, já que diferentes editores interpretam a tabulação de forma diferente.

Regras de declaração

  • Sempre termine uma declaração simples com ponto-e-vírgula.
  • Em declarações complexas, abra parênteses, colchetes e chaves no final da primeira linha.
  • Use um espaço antes de abrir parênteses, colchetes e chaves.
  • Feche parênteses, colchetes e chaves em uma nova linha, sem espaços antes.
  • Não finalize uma declaração complexa com ponto-e-vírgula.

Regras de objetos

  • Abra parênteses, colchetes e chaves na mesma linha do nome do objeto.
  • Use uma vírgula e um espaço entre cada propriedade e seu valor.
  • Use aspas para valores de strings, mas não para valores numéricos.
  • Não adicione vírgulas após o último par de propriedade/valor.
  • Feche parênteses, colchetes e chaves em uma nova linha, sem espaços antes.
  • Sempre finalize uma definição de objeto com ponto-e-vírgula.
  • Objetos pequenos (mais curtos) podem ser escritos em uma só linha, usando espaços somente entre as propriedades.

Limite de caracteres

Para facilitar a leitura, use um limite de 80 caracteres por linha. Se a declaração não couber em uma linha, quebre-a após um operador ou uma vírgula.

Convenções de nomenclatura

Sempre use as mesmas convenções de nomenclatura em todos os seus projetos de código. Por exemplo:

  • Nomes de variáveis e funções devem ser escritos em camelCase
  • Variáveis globais devem ser escritas em letras maiúsculas (não é obrigatório, mas recomendado)
  • Constantes (como PI) devem ser escritas em letras maiúsculas
  • Não use hifens nos nomes dos identificadores, substitua por sublinhados ou camelCase
  • Não use o símbolo de cifrão ($), pois isso pode causar conflitos com bibliotecas do JavaScript

Como carregar o JavaScript no HTML

Use uma sintaxe simples para carregar scripts externos (o atributo type não é necessário):

					
						<script src="meuscript.js"></script>

Como acessar objetos do HTML

Uma consequência de usar estilos HTML "bagunçados" é que podem ocorrer erros no JavaScript. As duas declarações a seguir produzem resultados diferentes:

					
						const obj = getElementById("Demo")

						const obj = getElementById("demo")

Sempre que possível, use a mesma convenção de nomenclatura usada no HTML.

Extensões de arquivos

Arquivos HTML devem ter a extensão .html (ou .htm), arquivos CSS devem ter a extensão .css e arquivos JavaScript devem ter a extensão .js.

Nomes de arquivos devem sempre ser escritos em letras minúsculas, porque a inconsistência pode gerar erros.

Práticas recomendadas

Evite variáveis globais

Evite variáveis globais para todos os tipos de dados, objetos e funções, já que elas podem ser sobrescritas por outros scripts.

Declarações no topo

As declarações no topo são uma prática recomendada que faz o seguinte:

  • Deixa o código mais limpo
  • Fornecem um local exclusivo para todas as variáveis locais
  • Facilitam evitar o uso de variáveis globais (que são indesejadas)
  • Reduzem a possibilidade de declarações repetidas

Isso também é indicado para variáveis de loops.

Inicialização de variáveis

Inicializar variáveis após sua declaração é uma prática recomendada que faz o seguinte:

  • Deixa o código mais limpo
  • Fornece um local exclusivo para iniciar as variáveis
  • Evita valores indefinidos

Isso mostra o uso pretendido da variável e seu tipo de dado.

Não use new Object()

  • Use "" em vez de new String()
  • Use 0 em vez de new Number()
  • Use false em vez de new Boolean()
  • Use {} em vez de new Object()
  • Use [] em vez de new Array()
  • Use /()/ em vez de new RegExp()
  • Use function (){} em vez de new Function()

Cuidado com conversões automáticas de tipos

Como variáveis no JavaScript podem ter qualquer tipo de dado, elas podem ser convertidas para qualquer outro tipo de dado. Isso pode provocar erros. Por exemplo:

						
							let x = "Hello"; // typeof x é string
							x = 5; // typeof x muda para number

Tenha cuidado também com números, já que eles podem ser convertidos em strings, e isso pode gerar resultados de operações com NaN.

Sempre use três sinais de igual

Sempre use === ao fazer comparações: == sempre converte (para o tipo correspondente) antes da comparação, === força a comparação de valor e tipo.

Padronize os parâmetros

Ao chamar uma função com um argumento ausente, o valor do argumento ausente é definido como undefined. Valores indefinidos podem quebrar o código, então recomenda-se atribuir valores padrão aos argumentos.

						
							function minhaFuncao(x, y) {
								if (y === undefined) {
									y = 0;
								}
							}

							OU

							function (a=1, b=1) { 
								/*código da função*/
							}

Finalize os switch com default

Sempre finalize uma declaração switch com default, mesmo se achar que não há razão para isso.

						
							switch (new Date().getDay()) {
								case 0:
									dia = "Domingo";
									break;
								case 1:
									dia = "Segunda";
									break;
								case 2:
									dia = "Terça";
									break;
								case 3:
									dia = "Quarta";
									break;
								case 4:
									dia = "Quinta";
									break;
								case 5:
									dia = "Sexta";
									break;
								case 6:
									dia = "Sábado";
									break;
								default:
									dia = "Desconhecido";
							}

Evite usar números, strings e booleanos como objetos

Sempre trate esses tipos de dados como primitivos, nunca como objetos. Declará-los como objetos reduz a velocidade de execução do código e pode gerar erros graves.

Evite usar eval()

Usamos essa função para executar um texto como código. Em quase todas as situações, não deve ser necessário usá-la, já que isso pode fazer com que um código malicioso seja executado, causando um problema de segurança.

Sobre o desempenho do JavaScript

Vejamos como acelerar a velocidade de execução do JavaScript.

Reduza a atividade em loops

Cada declaração de um loop, incluindo o for, é executado em cada iteração do loop. Colocar declarações ou atribuições fora do loop faz ele executar mais rápido.

					
						for (let i = 0; i < arr.length; i++) {} // errado

						let l = arr.length;
						for (let i = 0; i < l; i++) {} // certo

Reduza o acesso ao DOM

Acessar o DOM do HTML demora muito em comparação com outras declarações do JavaScript. Se acha que vai acessar um elemento do DOM com frequência,, acesse-o uma vez e use-o como uma variável local.

					
						const obj = document.getElementById("demo");
						obj.innerHTML = "Hello";

Reduza o tamanho do DOM

Use poucos elementos do DOM HTML. Isso sempre melhora o carregamento da página e acelera seu processamento (exibição da página), especialmente em dispositivos menores. Assim, cada tentativa de procurar no DOM (como getElementsByTagName) será mais rápida.

Evite variáveis desnecessárias

Não crie novas variáveis se não planeja salvar seus valores.

					
						// Substitua isso:

						let nomeCompleto = primeiroNome + " " + sobrenome;
						document.getElementById("demo").innerHTML = nomeCompleto;

						// Por isso:

						document.getElementById("demo").innerHTML = primeiroNome + " " + sobrenome;

Atrase o carregamento do JavaScript

Colocar seus scripts no final do corpo da página HTML possibilita que o navegador carregue a página primeiro. Enquanto o script está sendo baixado, o navegador não carrega mais nada. Além disso, toda a atividade de processamento pode ser bloqueada.

Uma alternativa é usar defer="true" na tag script. Esse atributo define que o script deve ser executado após o processamento da página, mas só funciona para scripts externos.

Se possível adicione o script diretamente no HTML, no final da página.

Evite usar with

Evite usar a palavra-chave with, já que ela pode afetar negativamente a velocidade da página e bagunça os escopos do JavaScript. Essa palavra-chave não é permitida no modo restrito.

break byte case catch
char class* const* continue

export* extends* false final
finally float for function

in instanceof int interface
let* long native new
null package private protected
public return short static
super* switch synchronized this
throw throws transient true
try typeof var void
volatile while with yield

As seguintes palavras reservadas foram removidas no ECMAScript 5/6 (2015):

abstract boolean byte char
double final float goto
int long native short
synchronized throws transient volatile

Porém, ainda não é possível usá-las como nomes de variáveis.
