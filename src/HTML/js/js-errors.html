Erros

Declarações de erros

Há quatro declarações que definem erros:

  • try: define um bloco de código a ser executado (para teste).
  • catch: define um bloco de código que lida com qualquer erro.
  • finally: define um bloco de código a executar independentemente do resultado.
  • throw: define um erro personalizado.

Erros acontecem!

Ao executar códigos JavaScript, podem ocorrer diferentes erros, que podem ter sido cometidos pelo programador (como erros de digitação), pelo usuário (uma inserção incorreta) ou outras coisas que não se pode prever.

Quando ocorre um erro, o JavaScript geralmente pára e gera uma mensagem de erro. Em termos técnicos: o JavaScript exibe uma exceção (ou um erro).

Na verdade, o JavaScript cria um objeto de erro (Error object) com duas propriedades: nome (name) e mensagem (message).

try e catch

Essas duas declarações funcionam como um par: try possibilita definir um bloco de código a ser testado durante a execução, enquanto catch possibilita definir um bloco de código a executar se ocorrer um erro em try. Sintaxe:

				
					try {
						Bloco de código a testar
					}
					catch(err) {
						Bloco de código para lidar com os erros
					}

throw

A declaração throw possibilita criar um erro personalizado, isto é, exibir uma exceção (ou um erro), que pode ser uma sequência de caracteres, um número, um booleano ou um objeto. Por exemplo:

				
					throw "Grande demais"; // exibe um texto
					throw 500; // exibe um número

Usando throw com try e catch, é possível controlar o fluxo do programa e gerar mensagens de erro personalizadas.

finally

Esta declaração permite executar um código após a execução de try e catch, independentemente do resultado. Sintaxe:

				
					try {
						Bloco de código a testar
					}
					catch(err) {
						Bloco de código para lidar com os erros
					}
					finally {
						Bloco de código a executar independentemente do resultado de try/catch
					}

Exemplo de validação de dados

O exemplo a seguir analisa os dados inseridos. Se o valor estiver incorreto, exibe um erro, que aciona a declaração catch para exibir um erro personalizado.

				
					<!DOCTYPE html>
					<html>
					<body>

					<p>Please input a number between 5 and 10:</p>

					<input id="demo" type="text">
					<button type="button" onclick="myFunction()">Test Input</button>
					<p id="p01"></p>

					<script>
					function myFunction() {
						const message = document.getElementById("p01");
						message.innerHTML = "";
						let x = document.getElementById("demo").value;
						try {
							if(x.trim() == "") throw "empty";
							if(isNaN(x)) throw "not a number";
							x = Number(x);
							if(x < 5) throw "too low";
							if(x > 10) throw "too high";
						}
						catch(err) {
							message.innerHTML = "Input is " + err;
						}
					}
					</script>

					</body>
					</html>

Navegadores modernos geralmente combinam JavaScript e HTML para validar os dados inseridos, usando regras de validação predefinidas nos atributos HTML: <input id="demo" type="number" min="5" max="10" step="1">. Saiba mais em Validação de formulários e em .

O objeto Error

O JavaScript oferece um objeto de erro incorporado, que exibe informações quando ocorre um erro. Esse objeto tem duas propriedades úteis: name, que define ou retorna um nome de erro, e message, que define ou retorna uma mensagem de erro (um texto, em formato String).

Valores dos nomes de erros

Há seis valores para a propriedade name. Vejamos as descrições abaixo.

EvalError

Exibido quando ocorre um erro na função eval(). Porém, versões mais recentes do JavaScript não exibem esse erro, exibem SyntaxError.

RangeError

Exibido quando o número inserido está fora do "limite" permitido. Por exemplo, não é possível definir um número com 500 dígitos significativos.

						
							let num = 1;
							try {
								num.toPrecision(500);   // A number cannot have 500 significant digits
							}
							catch(err) {
								document.getElementById("demo").innerHTML = err.name;
							}

ReferenceError

Exibido ao fazer referência a uma variável que ainda não foi declarada.

SyntaxError

Exibido ao tentar avaliar um código com erros de sintaxe, por exemplo, quando falta um ponto ou ao não fechar aspas.

TypeError

Exibido se um operando ou argumento for incompatível com o tipo esperado por um operador ou função. Por exemplo, não é possível converter um número com toUpperCase()

URIError

Exibido ao usar caracteres ilegais em uma função de URI.

						
							decodeURI("%%%"); // Não é possível decodificar sinais de porcentagem

Propriedades não padrão do objeto Error

A Mozilla e a Microsoft definiram outras propriedades para o objeto Error:

  • fileName (Mozilla)
  • lineNumber (Mozilla)
  • columnNumber (Mozilla)
  • stack (Mozilla)
  • description (Microsoft)
  • number (Microsoft)

Não use essas propriedades em sites públicos, já que elas não funcionam em todos os navegadores.
