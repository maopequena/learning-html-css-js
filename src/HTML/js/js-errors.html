Erros

Erros acontecem!

Ao executar códigos JavaScript, podem ocorrer diferentes erros, que podem ter sido cometidos pelo programador (como erros de digitação), pelo usuário (uma inserção incorreta) ou outras coisas que não se pode prever.

Quando ocorre um erro, o JavaScript geralmente pára e gera uma mensagem de erro. Em termos técnicos: o JavaScript exibe uma exceção (ou um erro).

Na verdade, o JavaScript cria um objeto de erro (Error object) com duas propriedades: nome (name) e mensagem (message).

Declarações de erros

Há quatro declarações que definem erros:

  • try: define um bloco de código a ser executado (para teste).
  • catch: define um bloco de código que lida com qualquer erro.
  • finally: define um bloco de código a executar independentemente do resultado.
  • throw: define um erro personalizado.

try e catch

Essas duas declarações funcionam como um par: try possibilita definir um bloco de código a ser testado durante a execução, enquanto catch possibilita definir um bloco de código a executar se ocorrer um erro em try. Sintaxe:

				
					try {
						Bloco de código a testar
					}
					catch(err) {
						Bloco de código para lidar com os erros
					}

throw

A declaração throw possibilita criar um erro personalizado, isto é, exibir uma exceção (ou um erro), que pode ser uma sequência de caracteres, um número, um booleano ou um objeto. Por exemplo:

				
					throw "Grande demais"; // exibe um texto
					throw 500; // exibe um número

Usando throw com try e catch, é possível controlar o fluxo do programa e gerar mensagens de erro personalizadas.

finally

Esta declaração permite executar um código após a execução de try e catch, independentemente do resultado. Sintaxe:

				
					try {
						Bloco de código a testar
					}
					catch(err) {
						Bloco de código para lidar com os erros
					}
					finally {
						Bloco de código a executar independentemente do resultado de try/catch
					}

Exemplo de validação de dados

O exemplo a seguir analisa os dados inseridos. Se o valor estiver incorreto, exibe um erro, que aciona a declaração catch para exibir um erro personalizado.

			
				<!DOCTYPE html>
				<html>
				<body>

				<p>Please input a number between 5 and 10:</p>

				<input id="demo" type="text">
				<button type="button" onclick="myFunction()">Test Input</button>
				<p id="p01"></p>

				<script>
				function myFunction() {
					const message = document.getElementById("p01");
					message.innerHTML = "";
					let x = document.getElementById("demo").value;
					try {
						if(x.trim() == "") throw "empty";
						if(isNaN(x)) throw "not a number";
						x = Number(x);
						if(x < 5) throw "too low";
						if(x > 10) throw "too high";
					}
					catch(err) {
						message.innerHTML = "Input is " + err;
					}
				}
				</script>

				</body>
				</html>

Navegadores modernos geralmente combinam JavaScript e HTML para validar os dados inseridos, usando regras de validação predefinidas nos atributos HTML: <input id="demo" type="number" min="5" max="10" step="1">. Saiba mais em Validação de formulários e em .

O objeto Error

O JavaScript oferece um objeto de erro incorporado, que exibe informações quando ocorre um erro. Esse objeto tem duas propriedades úteis: name, que define ou retorna um nome de erro, e message, que define ou retorna uma mensagem de erro (um texto, em formato String).

Valores dos nomes de erros

Há seis valores para a propriedade name. Vejamos as descrições abaixo.

EvalError

Exibido quando ocorre um erro na função eval(). Porém, versões mais recentes do JavaScript não exibem esse erro, exibem SyntaxError.

RangeError

Exibido quando o número inserido está fora do "limite" permitido. Por exemplo, não é possível definir um número com 500 dígitos significativos.

						
							let num = 1;
							try {
								num.toPrecision(500);   // A number cannot have 500 significant digits
							}
							catch(err) {
								document.getElementById("demo").innerHTML = err.name;
							}

ReferenceError

Exibido ao fazer referência a uma variável que ainda não foi declarada.

SyntaxError

Exibido ao tentar avaliar um código com erros de sintaxe, por exemplo, quando falta um ponto ou ao não fechar aspas.

TypeError

Exibido se um operando ou argumento for incompatível com o tipo esperado por um operador ou função. Por exemplo, não é possível converter um número com toUpperCase()

URIError

Exibido ao usar caracteres ilegais em uma função de URI.

						
							decodeURI("%%%"); // Não é possível decodificar sinais de porcentagem

Propriedades não padrão do objeto Error

A Mozilla e a Microsoft definiram outras propriedades para o objeto Error:

  • fileName (Mozilla)
  • lineNumber (Mozilla)
  • columnNumber (Mozilla)
  • stack (Mozilla)
  • description (Microsoft)
  • number (Microsoft)

Não use essas propriedades em sites públicos, já que elas não funcionam em todos os navegadores.

Depuração

Um código pode conter erros sintáticos ou lógicos. Pode ser difícil diagnosticar esses erros.

Quando há erros, geralmente não acontece nada: não aparecem mensagens de erro e você não receberá informações do que corrigir. Procurar e corrigir error no código chama-se depuração, que é o processo de testar, localizar e mitigar erros.

Depurar não é uma tarefa fácil. Felizmente, todos os navegadores modernos têm um depurador JavaScript incorporado, que podem ser ativados e desativados, forçando o relatório de erros ao usuário.

Com um depurador, também é possível definir pontos de parada (breakpoints), pontos do código em que o depurador deve parar a execução e, assim, examinar as variáveis durante a execução do código.

Geralmente é só pressionar a tecla F12 no teclado e selecionar Console para ativar o depurador. Caso contrário, siga as instruções na parte inferior desta página.

console.log()

Se seu navegador oferece suporte à depuração, use o método console.log() para exibir valores do JavaScript na janela de depuração:

			
				<!DOCTYPE html>
				<html>
				<body>

				<h1>Minha primeira página da Web</h1>

				<script>
				a = 5;
				b = 6;
				c = a + b;
				console.log(c);
				</script>

				</body>
				</html>

Saiba mais sobre este método na Referência sobre objetos de JavaScript no site da W3Schools.

Definir pontos de parada

Na janela do depurador, podemos definir pontos de parada no código JavaScript.

A cada ponto de parada, o JavaScript para a execução e possibilita examinar os valores. Após isso, você pode retomar a execução do código (geralmente com um botão Reproduzir  ).

debugger

a palavra-chave debugger para a execução do código JavaScript e chama, se disponível, a função de depuração, que é o mesmo que adicionar um ponto de parada na janela do depurador.

Se não estiver disponível no navegador, esta palavra-chave não tem efeito.

Erros comuns no JavaScript

Usar erroneamente o operador de atribuição

Programas JavaScript podem gerar resultados inesperados se for usado acidentalmente um operador de atribuição (=) em vez de um de comparação (==) em uma declaração if.

Um operador de atribuição sempre retorna o valor da atribuição.

					
						let x = 0;

						if (x == 10); // Retorna false (como esperado), já que 10 != 0
						if (x = 10); // Retorna true, pois 10 é verdadeiro
						if (x = 0); // Retorna false, porque 0 é falso

Comparações não restritas

Em uma comparação normal, o tipo de dados não importa. Na comparação restrita, o tipo de dados importa. E é comum esquecer que uma declaração switch usa comparações restritas.

					
						let x = 10;
						let y = "10";

						if (x == y); // Retorna true
						if (x === y); // Retorna false
						
						switch(x) {
							case 10: alert("Hello");
						} // Exibe um alerta com "Hello"
						switch(x) {
							case "10": alert("Hello");
						} // Não exibe um alerta

Confundir adição e concatenação

A adição soma números, a concatenação une cadeias de caracteres, apesar de ambas as operações usarem o mesmo operador (+). Devido a isso, somar números com cadeias de caracteres pode ter resultados inesperados.

					
						let x = 10;
						x = 10 + 5;       // Aqui x é 15

						let y = 10;
						y += "5";        // Aqui y é "105"

Não entender floats

Todos os números no JavaScript são armazenados como números de ponto flutuante de 64-bits (floats). Todas as linguagens de programação, incluindo o JavaScript, têm dificuldades com a precisão de valores de ponto flutuante. Para resolver esse problema, o ideal é fazer cálculos de multiplicação e divisão.

					
						let x = 0.1;
						let y = 0.2;
						let z = x + y // o resultado de z não é 0.3, mas 0.30000000000000004

						let z = (x * 10 + y * 10) / 10; // com multiplicação e divisão, z é 0.3

Quebrar strings

O JavaScript permite quebrar uma declaração em duas linhas, mas não é possível quebrar uma cadeia de caracteres. Para quebrar uma cadeia de caracteres, use uma barra invertida (\).

					
						let x =
						"Hello World!"; // isso é permitido

						let x = "Hello
						World!"; // isso é inválido

						let x = "Hello \
						World!"; // isso é permitido

Uso incorreto do ponto-e-vírgula

Usar o ponto-e-vírgula incorretamente pode fazer com que o código seja executado mesmo se uma declaração if não for válida:

					
						if (x == 19);
						{
							// bloco de código a executar
						}

Quebrar uma declaração return

O comportamento padrão no JavaScript é fechar uma declaração automaticamente no final da linha e permitir quebrar uma declaração em duas linhas. Por causa disso, o ponto-e-vírgula no final não faz diferença na última declaração de um bloco de código. Porém, ao quebrar uma declaração fechada com ponto-e-vírgula na última linha, a função retorna undefined.

					
						function myFunction(a) {
							let power = 10 
							return a * power // permitido
						}

						function myFunction(a) {
							let power = 10;
							return a * power; // permitido
						}

						function myFunction(a) {
							let
							power = 10; // permitido
							return a * power;
						}

						function myFunction(a) {
							let
							power = 10; 
							return
							a * power; // undefined
						}

Por quê? Porque para o JavaScript, o último bloco de código significa o seguinte:

					
						function myFunction(a) {
							let
							power = 10; 
							return;
							a * power;
						}

Assim, a recomendação é nunca quebrar uma declaração com return e sempre usar ponto-e-vírgula.

Acessar matrizes com índices nomeados

Muitas linguagens de programação oferecem suporte a matrizes com índices nomeados, que são chamadas de matrizes associativas (ou hashes). O JavaScript não é uma dessas linguagens. No JavaScript, as matrizes têm índices numerados.

No JavaScript, os objetos usam índices nomeados. Portanto, ao usar um índice nomeados ao acessar matrizes, o JavaScript redefinirá a matriz como um objeto. Após essa redefinição, os métodos e propriedades de matrizes resultarão em undefined ou gerarão resultados incorretos.

Finalizar definições com vírgula

Deixar uma vírgula no final de objetos e matrizes é permitido no ECMAScript 5. Por exemplo:

					
						pessoa = {primeiroNome:"John", sobrenome:"Doe", idade:46,};

						pontos = [40, 100, 1, 5, 25, 10,];

Porém isso pode gerar problemas com os navegadores antigos e o JSON não aceita essas vírgulas "soltas". A recomendação é não deixar vírgulas soltas.

Indefinido não é nulo

Objetos, variáveis, propriedades e métodos do JavaScript podem ser undefined. Além disso, objetos vazios podem ter o valor null. Isso pode dificultar testar se um objeto está vazio, mas é possível fazer isso testando se o tipo é undefined.

					
						if (typeof myObj === "undefined")

Porém, não é possível testar se um objeto é null, porque isso gera um erro se o objeto for undefined.

Para solucionar este problema, teste se o objeto não é null e não é undefined, mas saiba que isso ainda pode gerar um erro se undefined for testado antes de null.
